# Maatribhasha Backend & Integrated Bilingual Generator

> **SIH Problem Statement 26042**: Context-Aware Multilingual Classroom Assistant for Primary Tribal Education in Jharkhand.

The Maatribhasha Backend is a high-performance **Modular Monolith** engineered in **FastAPI**, **SQLAlchemy 2.0**, and **Pydantic v2**. It connects with **Supabase** (PostgreSQL, Auth, and Storage) to provide synchronization, curriculum management, language-pack distribution, translation review queues, and server-side generative AI orchestration.

This repository integrates the **Bilingual FLN Generator**, enabling teachers, curriculum designers, and language experts to generate, validate, human-review, and publish bilingual (Hindi-Santali, Ho, Mundari) educational materials (worksheets, flashcards, lesson plans) aligned with NIPUN Bharat standards.

### Architectural Principles:
1. **Live Classroom is 100% Offline**: Live classroom speech translation, vocabulary lookup, and lesson delivery run locally on the Flutter tablet using on-device models. The live classroom **never** blocks on or requires backend or LLM availability.
2. **Server-Side AI Orchestration**: LLM inference (Google Gemini or Mock Provider) runs strictly on the backend. No API keys or service-role credentials are ever sent to client devices.
3. **No Unapproved Content in Production**: Content generated by AI is stored in `generated_content` in `GENERATED` status. It **cannot** be published to the catalog (`worksheets` / `flashcards`) or distributed to tablets until all human review gates pass.
4. **Integration Without Duplication**: The backend invokes the generator via `BilingualGeneratorService`. The backend does not duplicate the generator's prompt composition, validation, or review logic.

## 3. Bilingual Generator

The **Bilingual Generator** (`generator/`) is an autonomous modular pipeline responsible for generating, validating, and managing human reviews for bilingual educational content.

### Pipeline Stages:
1. **Curriculum & Blueprint**:
   - `generator/canonical/curriculum_master_v1.json`: Authoritative NIPUN Bharat learning outcomes and pedagogical boundaries for Grades 1 & 2.
   - `generator/blueprint/content_blueprint_v1.json`: Structured specifications for worksheets and flashcards (item counts, question formats, allowed number ranges, language modes).
2. **Prompt Composition**:
   - `generator/generation/compose_prompt.py` (`PromptComposer`): Assembles system prompts, domain-specific templates, and language guidance (Hindi, Santali Ol Chiki / Devanagari) while resolving all variables.
3. **LLM Providers**:
   - `MockProvider`: Fast, deterministic mock provider for testing and offline development.
   - `GeminiProvider`: Google Gemini provider using official `google-genai` SDK with structured JSON outputs.
   - `SarvamProvider`: Sarvam AI provider using official `sarvamai` SDK (`sarvam-105b`) with structured JSON Schema outputs.
4. **Validation**:
   - `generator/generation/schema/generated_content.schema.json`: JSON Schema Draft 2020-12 validation.
   - `generator/generation/validation/content_validator.py`: Pedagogical rules (grade-appropriate number limits, sum limits, option count, Santali script purity, answer key verification).
5. **Human Review Workflow**:
   - `generator/generation/review/review_manager.py` (`ReviewManager`): Manages review records with required gates:
     - `hindi`: Hindi language naturalness, age appropriateness.
     - `santali`: Santali language naturalness, script accuracy.
     - `curriculum`: Alignment with NIPUN learning outcomes and grade limits.
     - `answer_key`: Verification of correct answers.
     - `provisional_range`: Acknowledgment for provisional pilot items.
     - `santali_script_confirmed`: Confirmed script (e.g., `Olck` for Ol Chiki).
6. **Publication**:
   - `generator/generation/publishing/publisher.py` (`SupabasePublisher`): Verifies SHA256 integrity and all review gates, uploads assets to Supabase Storage, and persists records to `worksheets` / `flashcards` and `generated_content`.

## 4. Supabase Integration

### PostgreSQL Tables:
- **`generated_content`**: Stores all AI-generated units with raw LLM output, validation status, prompt provenance, and review notes.
- **`worksheets`**: Catalog of published worksheets containing titles, grade, subject, storage file path, file size, and learning outcome IDs.
- **`flashcards`**: Catalog of published bilingual vocabulary flashcards containing deck names, front text, back text, image URLs, audio URLs, and grade.
- **`languages`**: Supported regional and tribal languages (Hindi, Santali, Ho, Mundari).
- **`learning_outcomes`**: NIPUN Bharat competency and outcome codes.

### Supabase Storage:
- **Bucket**: `content`
- **Conventions**:
   - **Worksheets**: `worksheets/{grade}/{curriculum_id}/{content_id}.json` (and `.pdf` when rendered)
   - **Flashcards**: `flashcards/{grade}/{curriculum_id}/{content_id}_{asset_id}.png`
- **Rollback Safety**: If database persistence fails after assets are uploaded, all newly uploaded storage objects are rolled back automatically.

## 8. Development Workflow: Generate, Review & Publish

### Stage 1: Generate Content
Send a POST request to `/api/v1/ai/generate`:

```json
POST /api/v1/ai/generate
Content-Type: application/json
Authorization: Bearer <TEACHER_OR_REVIEWER_TOKEN>

{
  "blueprint_id": "BP-G1-NUM-032-01",
  "content_type": "worksheet",
  "target_language": "sat",
  "provider": "mock",
  "mock_mode": true,
  "force": true
}
```

**Response (201 Created)**:
```json
{
  "id": "GC-G1-NUM-032-01-bi-v1",
  "content_type": "worksheet",
  "prompt_used": "Blueprint: BP-G1-NUM-032-01 (Provider: mock)",
  "status": "GENERATED",
  "raw_output": { ... },
  "validated_output": { ... },
  "created_at": "2026-09-20T10:00:00Z"
}
```

### Stage 2: Review Content
Inspect review gates via `GET /api/v1/ai/content/{content_id}/review`:

```json
GET /api/v1/ai/content/GC-G1-NUM-032-01-bi-v1/review
Authorization: Bearer <REVIEWER_TOKEN>
```

Approve gates via `POST /api/v1/ai/content/{content_id}/review`:

```json
POST /api/v1/ai/content/GC-G1-NUM-032-01-bi-v1/review
Content-Type: application/json
Authorization: Bearer <REVIEWER_TOKEN>

{
  "status": "approved",
  "gates": {
    "hindi": "pass",
    "santali": "pass",
    "curriculum": "pass",
    "answer_key": "pass",
    "provisional_range": "pass"
  },
  "santali_script_confirmed": "Olck",
  "notes": "Reviewed mathematical limits and Ol Chiki script rendering."
}
```

### Stage 3: Publish Content
Publish to Supabase Storage and database catalogs:

```json
POST /api/v1/ai/content/GC-G1-NUM-032-01-bi-v1/publish
Content-Type: application/json
Authorization: Bearer <REVIEWER_TOKEN>

{
  "dry_run": false,
  "publish_to_catalog": true
}
```

**Response (200 OK)**:
```json
{
  "content_id": "GC-G1-NUM-032-01-bi-v1",
  "content_type": "worksheet",
  "status": "published",
  "is_idempotent": false,
  "record_ids": {
    "generated_content_id": "a9b6d8f0-...",
    "entity_id": "6c4fc0d9-..."
  },
  "storage_paths": [
    "worksheets/1/G1-NUM-032/GC-G1-NUM-032-01-bi-v1.json"
  ]
}
```

Re-submitting the publish request is **idempotent** and will return `"status": "already_published"` without error.

## 9. API Endpoints Reference

### AI & Bilingual Generator (`/api/v1/ai`)
- `POST /api/v1/ai/teacher/generate` (also `/api/v1/ai/content/generate`): Asynchronous teacher generation endpoint using Sarvam-105B or Gemini with full validation and review gates.
- `GET /api/v1/ai/jobs/{job_id}`: Poll generation job status (`PENDING`, `GENERATING`, `VALIDATING`, `REVIEW_REQUIRED`, `APPROVED`, `READY`, `FAILED`).
- `POST /api/v1/ai/jobs/{job_id}/approve`: Teacher/Reviewer approval of human review gates (e.g. `santali_script_confirmed` for Ol Chiki).
- `POST /api/v1/ai/generate`: Synchronous generation from blueprint or NIPUN learning outcome (Admin/Reviewer).
- `GET /api/v1/ai/content`: List generated content in review workflow.
- `GET /api/v1/ai/content/{id}`: Get single generated content unit.
- `GET /api/v1/ai/content/{id}/review`: Get review record, status, and gate checks.
- `POST /api/v1/ai/content/{id}/review`: Update review gates, status, and notes (Reviewer/Admin only).
- `POST /api/v1/ai/content/{id}/publish`: Publish approved content to Supabase Storage & catalogs (Reviewer/Admin only).
- `PATCH /api/v1/ai/content/{id}/status`: Legacy status transition and cataloging.

### Curriculum & Catalogs
- `GET /api/v1/languages`: Supported languages (Hindi, Santali, Ho, Mundari).
- `GET /api/v1/nipun/outcomes`: NIPUN Bharat learning outcomes.
- `GET /api/v1/worksheets`: Published worksheets catalog.
- `GET /api/v1/flashcards`: Published flashcards catalog.
- `GET /api/v1/lessons`: Teacher lesson plans.

### Offline Sync Engine
- `POST /api/v1/sync/upload`: Ingest batched offline operations with idempotency.
- `POST /api/v1/sync/check`: Check for released packs and curriculum updates.
- `GET /api/v1/sync/manifest`: Full metadata manifest of released assets.

## 10. Security & Secret Protection

- **Server-Side Isolation**: `GEMINI_API_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are strictly confined to the backend server.
- **Client Token Verification**: All client requests are authenticated using Supabase Auth JWTs. Role-based access control enforces `teacher`, `content_reviewer`, and `admin` scopes.
- **Audit Trails**: Every review decision records the reviewer ID, date, and gate confirmation in `review_notes` and review records.

## 11. Troubleshooting & Known Limitations

- **Mock vs. Live Gemini**: When running locally without a `GEMINI_API_KEY`, pass `"mock_mode": true` or `"provider": "mock"`. If `GEMINI_API_KEY` is omitted and Gemini is requested, the service will return an explicit error rather than silently faking an LLM response.
- **Windows UTF-8 Encoding**: On Windows PowerShell, Ol Chiki (Santali) and Devanagari (Hindi) console output requires UTF-8 mode. Set `$env:PYTHONIOENCODING="utf-8"` or run Python with `-X utf8` when executing CLI tools.
- **Supabase Mock Mode**: In local development with SQLite (`DATABASE_URL=sqlite+...`), `SupabasePublisher` operates with in-memory mock storage and repository, enabling full end-to-end testing without external network dependencies.
